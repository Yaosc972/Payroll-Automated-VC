# 定时同步与公共快照复用

2026-10-23 实施。公共资料按核算月份提前取数，新建活动直接复制已同步的资料并在本地计算；已有活动继续保留人工更正、特批、待办与采用版本。

## 使用方式

活动列表右上角新增“资料同步”。选择月份可查看国内、海外各自的采集时间、人员数、Offer 数及最近同步结果；“立即同步所选月份”在后台预取资料，不写核算活动。这里也可修改每天自动同步的北京时间，或暂停自动同步。

默认每天北京时间 **08:00**，预取本月、上月和仍未确认的历史活动月份。工作台服务需保持运行；服务启动时若已错过当天时间，会补跑一次。每个北京时间自然日记录处理结果，重复启动不重复当天已完成的月份；来源失败保留上次成功版本，可手动重试。海外取数继续使用已登录的 Ego 浏览器，登录失效会显示失败，不复制或更改凭据。

新建活动选择月份后，会显示准备采用的公共资料时间。创建时读取一次该月版本清单，校验原始内容摘要、来源与月份，将资料复制进新活动，再运行现有解析与核算。活动记录保存公共版本、原采集时间及本次采用时间。国内、海外分别采用最近成功版本，可能采集于不同时间，不将旧版本标成刚采集。

没有对应月份资料时仍可创建空活动，界面会明确提示；可先返回“资料同步”预取，或进入活动点击原有的“一键同步国内及海外”。已有活动的手动同步仍按现有规则另存资料供核对，不自动覆盖人工处理。后台刷新公共库不会更新已有活动。上月已确认结果仍需在新建时承接，或上传真实上月未结表；公共资料不代替期初、特批或人工决定。

## 实现位置与边界

- `bonus_platform/engine/recruitment_snapshot_library.py`：按月资料库、后台取数、版本校验、采用及每日工作线程。复用国内、海外现有只读连接器和校验器；额外补齐海外关联的国内领取人。同步查询范围包含同月活动人员及上月已确认记录中的历史人员，取出的公共资料不含活动人工决定或核算答案。
- `bonus_platform/engine/recruitment_activities.py`：在活动创建的暂存目录内采用快照，全部成功后原子发布活动。校验失败不会产生半成品活动。
- `bonus_platform/recruitment_draft_api.py`：公共资料查询、后台预取与定时设置 API。
- `scripts/preview_recruitment_flow.py` 和 `bonus_platform/app.py`：工作台服务生命周期启动、停止定时工作线程。隔离预览默认不启动外部同步；同时启用国内和海外连接时才启动。
- `bonus_platform/static/recruitment-activities.*`：公共资料入口、定时设置和新建活动中的采集时间提示；资料页原手动更新入口保留。

公共库位于当前数据根目录下的 `recruitment_shared_snapshots/`，与 `recruitment_activities/` 平级。每月 `latest.json` 指向不可变的 `versions/{domestic,overseas}/<SHA256>.json`；`job.json` 记录运行状态。公共目录限制为当前系统用户访问，快照文件权限 0600。定时设置、按日执行收据也保存在公共目录。

系统文件锁保证同一资料库只有一个公共取数任务，多个服务进程共用同一按日执行收据。定时刷新和手动预取不同时查询；刷新过程中创建活动仍可采用上次已发布版本。断电或进程退出后，遗留运行状态显示为中断，保留成功版本供手动恢复。

API（前缀 `/api/recruitment/activities`）：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /snapshot-library/{month}` | 月度快照摘要、最近任务与定时服务状态 |
| `POST /snapshot-library/{month}/refresh` | 后台预取指定月份；重复进行中的请求被拒绝 |
| `PATCH /snapshot-library/schedule` | 保存完整 `{enabled, hour, minute}`，北京时间 |

本次只启用本地 8187 工作台，没有生产发布或认证变更。已将上一轮真实接口采集的八月快照导入本地公共库，原采集时间保持不变；这一步没有重新请求 HR。其他月份将在定时运行或手动预取成功后可复用。
