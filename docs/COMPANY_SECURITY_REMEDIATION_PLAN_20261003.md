# 公司服务器外网发布安全整改方案

## 目标与范围

依据安全部《HRAS Global Payroll Workbench 渗透测试报告》（报告日期 2026-09-28），修复报告全部六项问题，并补齐与其同源的 API 鉴权遗漏。交付独立分支、回归证据和复测清单，供公司构建发布及安全部再次验证。

本方案保留已授权用户的核算规则、文件格式、模块入口及既有数据存储。访问变化集中于身份、模块权限、目录范围、运维信息和跳转地址。最终能否外网公布，以公司部署后的安全部复测及 IT 网络验收为准。

用户已选择“方案后直接修复、测试”。本次本地实施不直接发布生产，也不调用真实员工业务写入、北森同步、飞书通讯录同步或实际社保申报。

## 六项整改与验收

| 报告项 | 改造内容 | 复测必须观察到的结果 |
| --- | --- | --- |
| P0 餐补数据未授权访问 CWE-306 | 对整个正式工薪酬 API 执行会话和 `employee` 模块授权，覆盖上传、批次列表、明细和导出；检查发生在业务处理及存储读取之前。保留模块内部原有批次共享规则。 | 匿名和失效会话为 401，无模块权限为 403；响应无员工信息。已授权用户仍能上传、核算、查历史及导出相同结果。 |
| P1 任意目录枚举 CWE-22 | 四个材料入口共用受控目录逻辑；使用服务端明确配置的专用材料根，客户端不能选服务器任意目录。逐文件解析真实路径并限制在根内，阻止符号链接外逃；对外仅返回相对路径及安全错误。 | 匿名 401；`/app`、`.`、`..`、编码路径及符号链接不能枚举源码或外部目录。合法材料目录内的索引、预检和批次建立保持可用。 |
| P1 状态信息暴露 CWE-200 | 劳务状态 API 要求认证。业务用户保留限额、保留周期及本人批次审计摘要；存储桶、绝对路径、运维 probe 和全局审计限系统管理员或受验证的运维服务令牌。 | 匿名响应无路径、桶名、审计记录和构建详情；业务治理弹窗正常，管理员运维诊断正常。 |
| P2 版本门替代鉴权 CWE-862 | 正式操作先会话、模块权限、批次范围，再检查版本契约。保留原版本头及不匹配的 409；生产 owner/actor 来自会话。Worker 与运维通道使用精确路由和各自凭据。 | 匿名携带三个正确版本头仍为 401；无角色为 403；已授权用户旧版本仍为 409，正确版本执行原有流程。 |
| P2 登出开放跳转 CWE-601 | 修实际 `app.py` 登出路由，统一 Python 和登录页的安全跳转规则，只接受站内单斜杠路径，拒绝协议相对外链、反斜线、控制字及编码变体。 | 恶意 next 回退站内登录页，合法模块 query/hash 回跳正常；登出仍撤销会话并清 Cookie。 |
| P4 无效口令锁 API | 保留平台飞书会话和海外薪资模块授权，移除服务输出中历史共享口令 UI、`/api/unlock`、`/api/change-passcode` 和 URL sid 逻辑。保留原交接资源指纹及 18 个解析工具。 | 实际页面响应无失效接口和共享口令入口；18 个工具的上传、处理、历史恢复及下载仍正常。 |

报告“已覆盖测试访问”中的等级与汇总/详情不一致；本次按汇总及各漏洞详情的 P0/P1/P2/P4 优先级整改，不据此减少范围。

## 同源问题一起收敛

1. 公司容器与 AIDeploy 必须默认启用身份认证，生产禁用 mock 登录；明确区分部署环境与 Vercel serverless，以免改变公司后台任务和定时调度。
2. 餐补以外的招聘、社保及其他业务 API 也纳入服务端权限检查。前端 localStorage 仅作显示缓存，401/403/服务器错误/网络失败不回退到模拟管理员。
3. 生产关闭公开 `/docs`、`/redoc`、`/openapi.json`；健康检查仅输出最小可用状态。内部 API 清单由构建测试读取，不依赖公开文档。
4. 生产 CORS 仅允许明确配置的 HTTPS 来源和必要请求头；开发 `null`/localhost 仅留在本地模式。报告实测任意来源，与本地 FastAPI 配置不一致，因此须同步检查 nginx/网关是否追加宽松头。
5. 部署会话 Cookie 使用 Secure、HttpOnly、SameSite；复用现有会话库及飞书登录。公司 MySQL 的正常会话应被可信认证检查接受。
6. 容器构建排除本地凭据、运行批次、临时报告和生成的安装包，保留两份招聘规则/导入模板、海外工具资源及构建版本校验需要的 Worker 源码。

## 功能兼容与特殊通道

| 通道 | 认证与兼容规则 |
| --- | --- |
| 浏览器业务 | 平台会话、模块角色和既有批次范围；不得从请求体、localStorage 或版本头授予身份。 |
| Worker 设备管理和安装包 | 浏览器会话及模块权限；安装包上传发布保留系统管理员权限。 |
| Worker 执行 | 保留 Bearer 设备/用户、任务 owner、lease 和 generation 校验；不新增浏览器 Cookie 要求。 |
| Worker 激活 | 保留短期激活码和当前设备绑定流程，不能因整个 worker 前缀豁免而漏掉新接口。 |
| Cron 与运维 | 按精确路径执行原 Cron/运维令牌校验；不允许无凭据通用健康详情。 |
| 同域上传与下载 | 保留公司后端上传到 OBS 的路径，以及已授权下载和短期签名 URL。 |
| 材料管理 | 沿用默认材料集合业务功能，先核对现有 `LABOR_REFERENCE_MATERIALS_DIR` 是专用目录且已挂载。未配置时给安全业务错误。 |
| 旧批次 | 不改批次 ID、金额、结果或自动迁移 owner；发布前只读统计空 owner/`local-default`，存在时由管理员核对归属并制定迁移方案。 |

## 实施与测试顺序

1. 在独立工作树落地方案，新增隔离回归用例，观察现有实现失败。
2. 修服务端会话与权限、目录控制和跳转；同步修前端历史口令和权限回退。
3. 运行安全反例矩阵及现有权限、餐补、招聘、社保、海外工具、劳务 Worker、公司 MySQL/OBS 回归。测试仅使用隔离 SQLite、临时文件和模拟外部服务。
4. 检查差异，确保无核算规则、数据库 schema、生产凭据和真实业务数据变更。形成提交与复测证据。
5. 从实际公司 master 合并整改提交后构建，核对镜像和配置，再做部署验收；稳定后交安全部复测。

安全用例覆盖匿名、伪造/失效会话、无模块角色、合法角色、系统管理员、跨用户资源、正确/错误版本头、目录外逃、恶意 next、可信/不可信 Origin、撤销 Worker token 和过期 lease。仅验证 401 不代表合法用户功能验证通过，两组证据都需要。

## 公司 IT 配套工作

- 核对 AIDeploy 的实际发布来源、镜像 digest、生产变量名及 Preview 继承规则。验证 Preview 的 MySQL、OBS、连接器隔离，关闭自动同步副作用；继承生产配置的 Preview 不可用于业务写入测试。
- nginx/网关和应用统一 CORS 策略，清除重复的 `*` 或任意 Origin 反射。复测包含成功与错误响应。
- 验证 HTTPS 证书、TLS、可信转发头、飞书回调与 Secure Cookie；公司源站 8000 和 MySQL 不允许绕过网关直接访问。
- 报告记录的 LDAP 389 为网关资产，IT 核对它的监听、ACL 和公网路由，不能随业务域名一起外网开放。
- 核对 OBS 桶私有访问、最小服务权限、签名有效期和审计日志权限。应用角色限制不能代替桶权限。
- 限流、上传体积、请求超时及 WAF 配置应按现有文件大小、长任务和 Worker 轮询实测设置，不能以过小阈值阻断正常核算。
- 报告没有开展 Web 扫描、主机扫描或容器扫描。外网公布前由 IT/安全部补齐其要求的扫描和验收；本地单测不能替代这些结果。

## 发布、回滚与复测交付

生产发布前保留当前镜像、release、配置与数据备份。优先在独立测试环境验证上传、核算、历史批次、导出、Worker 和登录；没有独立环境时，不在继承生产库的预览中执行写入验收。

回滚只切回已备份镜像和对应配置，不回退数据库 schema 或覆盖业务数据。若外网已开放，回滚到有旧漏洞的镜像前必须先收回外网访问或在网关阻断漏洞接口，避免重新暴露数据。

向安全部提供每项编号、修复提交、实际部署版本、无员工信息的请求/响应和合法用户回归结论。六项问题逐项复测关闭，关联配置验收完成后再申请外网公布。当前文档是整改方案，不是安全部通过证明。
