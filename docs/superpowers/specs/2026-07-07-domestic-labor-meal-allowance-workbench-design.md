# 国内劳务餐补核算工作台设计方案

## 结论

国内劳务前端应从“一个批次里多选多个科目”调整为“先选择科目，再进入该科目的核算批次”。第一版以餐补作为样板科目，先跑通餐补的批次保留、数据上传、字段检查、结果核算、异常查看、员工解释和导出归档。

本方案不做多科目合并计算，不做审批流，不做线下答案差异对比，不做复杂大屏。

## 设计原则

- 一个科目一个工作台，避免多个科目的规则、异常和结果混在同一张表里。
- 一个核算批次对应一次可回看的餐补计算，支持同一月份多次试算或复算。
- 页面以表格核算为核心，顶部只保留定位、状态和必要动作。
- 异常、公式和审计解释围绕员工结果行展开，不单独做复杂复核页面。
- 视觉风格遵循项目 `DESIGN.md`：Sigma 蓝色企业后台、冷灰底、白色面板、表格优先、状态颜色只用于风险表达。

## 页面层级

```text
国内劳务首页
  └─ 科目入口
      └─ 餐补
          └─ 餐补核算批次列表
              ├─ 新建餐补批次
              └─ 餐补批次工作台
                  ├─ 数据上传
                  ├─ 字段检查
                  ├─ 餐补核算
                  └─ 导出归档状态
```

## 国内劳务首页

首页目标是让用户先选择本次要处理的薪酬科目，并能回看最近批次。

### 科目入口

展示四个科目卡片：

| 科目 | 第一版状态 | 主动作 |
|---|---|---|
| 餐补 | 样板科目，可进入批次列表 | 进入餐补核算 |
| 工龄奖 | 已配置，后续按同模式改造 | 进入工龄奖核算 |
| 全勤奖 | 已配置，后续按同模式改造 | 进入全勤奖核算 |
| 外宿补贴 | 已配置，后续按同模式改造 | 进入外宿补贴核算 |

卡片只展示关键状态：

- 本月是否已有核算批次
- 最近核算人数
- 异常数量
- 最近导出时间
- 规则版本

不要在卡片中放大段规则说明。规则说明放到科目工作台和员工解释里。

### 最近核算批次

首页下方保留最近批次列表，用于快速回看。

| 月份 | 科目 | 批次名称 | 状态 | 人数 | 应发金额 | 异常 | 操作 |
|---|---|---|---|---:|---:|---:|---|
| 2026-05 | 餐补 | 餐补初算 | 可导出 | - | - | - | 查看 |
| 2026-05 | 工龄奖 | 工龄奖复算 | 待复核 | - | - | - | 查看 |

## 餐补核算批次列表

点击餐补后进入“餐补核算批次列表”。它类似 FBU 的活动列表，但命名使用国内劳务业务语义。

### 批次表字段

| 字段 | 说明 |
|---|---|
| 核算月份 | 本批次对应月份 |
| 批次名称 | 如“2026年05月餐补初算” |
| 状态 | 草稿、已上传、字段异常、已核算、可导出、已导出 |
| 员工数 | 本批次覆盖员工数 |
| 应发合计 | 餐补应发总额 |
| 异常数 | 当前仍需关注的异常数 |
| 创建时间 | 批次创建时间 |
| 最近更新 | 最近一次上传、核算或导出时间 |
| 操作 | 进入、导出、删除草稿 |

### 新建餐补批次

新建时只填写必要信息：

- 核算月份
- 批次名称
- 备注，可选

创建后进入该批次工作台。

## 餐补批次工作台

工作台采用“顶部任务栏 + 顶部流程条 + 主表 + 右侧异常队列”的结构，不使用左侧流程栏。

### 顶部任务栏

一行即可：

```text
[2026年05月 餐补初算] [已核算]                    [返回批次列表] [重新核算] [导出结果]
```

顶部只承担定位和动作，不放大面积 KPI。

### 顶部流程条

流程条紧凑展示：

```text
数据上传 -> 字段检查 -> 餐补核算 -> 导出归档
```

状态包括：

- 未开始
- 当前
- 已完成
- 有异常

交互规则：

- 已完成和当前步骤可点击。
- 前置步骤未完成时，后续步骤置灰。
- 字段检查不通过时，不允许进入餐补核算。
- 导出归档不做独立大页面，只作为导出完成后的状态。

## 数据上传

“资料导入”统一改名为“数据上传”。

页面以资料清单呈现，不做占空间的大上传卡片。

| 数据 | 状态 | 用途 | 操作 |
|---|---|---|---|
| 日考勤数据 | 未上传 / 已上传 | 东莞餐补逐日计算 | 上传 / 替换 |
| 月考勤数据 | 未上传 / 已上传 | 嘉善/义乌汇总计算、人员字段补充 | 上传 / 替换 |

不展示“线下答案”入口。线下答案不参与平台核算，也不进入异常队列。

## 字段检查

字段检查按餐补规则需要分组展示。

### 基础员工字段

- 工号
- 姓名
- 一级部门
- 二级部门
- 岗位名称
- 工作地区
- 在职状态

### 东莞日考勤字段

- 日期
- 工作状态
- 正班时数
- 刷卡加班
- 异常标记
- 异常原因

### 嘉善/义乌月考勤字段

- 排班天数
- 实际在职工作日天数
- 事假时数
- 病假时数
- 旷工天数

字段状态只保留三种：

- 已识别
- 缺失
- 需确认

字段检查不通过时，不允许进入餐补核算。

## 餐补核算

餐补核算是核心页面。统计、筛选、结果表和导出按钮都在这个页面完成。

### 表格工具区

表格上方放统计和筛选。

统计：

- 应发合计
- 员工数
- 异常数
- 封顶人数

筛选：

- 搜索：工号、姓名、部门
- 工作地区：全部、东莞、嘉善、义乌、晋江、未识别
- 餐补资格：全部、享有、不享有、待确认
- 异常状态：全部、只看异常、只看阻断
- 金额状态：全部、应发大于 0、应发为 0

### 结果表字段

| 字段 | 用途 |
|---|---|
| 工号 | 识别员工 |
| 姓名 | 识别员工 |
| 工作地区 | 判断地区规则 |
| 一级部门 | 判断归属范围 |
| 二级部门 | 判断归属范围 |
| 岗位名称 | 判断是否享有 |
| 餐补资格 | 享有、不享有、待确认 |
| 有效出勤 | 展示参与餐补计算的天数或时数 |
| 扣减项 | 展示事假、病假、旷工等影响项 |
| 封顶前金额 | 展示公式计算结果 |
| 应发餐补 | 展示最终金额 |
| 异常状态 | 通过、提示、阻断 |
| 解释 | 打开员工解释抽屉 |

金额列右对齐，员工编号和金额使用等宽数字。

## 异常队列

右侧保留异常队列，可收起。异常队列只展示平台核算自身能判断的问题，不展示线下答案差异。

异常类型：

- 字段缺失
- 工作地区未识别
- 岗位不享有
- 金额为 0 但有有效出勤
- 日考勤异常标记导致不发
- 数据口径无法判断或需要人工补充

异常卡片字段：

- 异常等级：阻断、提示
- 员工：工号、姓名
- 问题：一句话说明
- 影响：是否影响发放或导出
- 建议动作：补字段、确认岗位、确认地区、无需处理

## 员工解释抽屉

点击员工行或“解释”后打开抽屉。

展示顺序：

1. 员工信息
   - 工号
   - 姓名
   - 部门
   - 岗位
   - 工作地区
   - 在职状态

2. 规则命中
   - 命中地区规则：东莞、嘉善/义乌、晋江
   - 是否享有餐补
   - 不享有时说明原因

3. 计算过程
   - 展示公式，不只展示结果

4. 明细
   - 东莞展示每日明细
   - 嘉善/义乌展示月度汇总字段
   - 晋江展示不享有原因

5. 异常与建议
   - 展示系统发现的问题
   - 展示建议处理方式

### 东莞解释口径

- 每日有效时数取正班时数和刷卡加班中的较高值。
- 若异常标记表示旷工，当日餐补为 0。
- 每日餐补满 8 小时按 19 元，不满 8 小时按时数折算。
- 月度封顶 500 元。

### 嘉善/义乌解释口径

- 餐补 = 300 / 排班天数 x 参与计算天数。
- 参与计算天数 = 实际在职工作日天数 - 事假天数 - 旷工天数 - 病假天数 x 0.4。
- 当前仍保留旷工扣减口径。

### 晋江解释口径

- 晋江不享有餐补，金额为 0。

## 导出归档

导出归档不做独立大页面。

规则：

- 餐补核算完成后，在餐补核算页显示“导出结果”按钮。
- 有阻断异常时不可导出。
- 只有提示异常时可以导出，但导出文件应带审计说明。
- 导出成功后，流程条中的“导出归档”变为已完成。
- 批次记录导出时间、导出文件名、导出状态。

## 第一版不做

- 多科目合并计算
- 审批流
- 线下答案差异对比
- 复杂图表大屏
- 批量人工改金额
- 规则配置后台
- 为导出归档单独做大页面

## 实施边界

第一版前端改造应只围绕国内劳务模块进行：

- `bonus_platform/static/domestic-labor.html`
- `bonus_platform/static/domestic-labor.js`
- 必要时补充国内劳务专属文档或测试

不应修改共享首页、共享样式、其他业务模块或后端接口，除非后续实施时确认必须调整并获得明确同意。
