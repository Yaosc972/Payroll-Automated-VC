# 海外劳务工报账核对 UAT/准上线架构 ADR

状态：Proposed  
日期：2026-06-20  
适用范围：海外劳务工报账核对模块，不扩展到 FBU、招聘奖金、国内劳务或其他共享模块。

## 背景

海外劳务工报账核对当前已经具备本地上传、字段映射、抽取比对、差异报告、测试材料验证、黄金回归工具雏形和 Vercel UAT 页面。但正式抽取链路仍存在两个 P1 风险：

- LAB-P1-001：抽取任务通过进程内 `run_in_executor` 启动，不能作为 Vercel Serverless 请求结束后的生产长任务方案。
- LAB-P1-002：Blob 持久化已有代码雏形，但还没有完成环境边界、并发一致性、幂等和跨实例验收。

当前代码证据：

- `bonus_platform/app.py` 中 `/api/labor/runs/{run_id}/extract-and-compare` 仍调用 `asyncio.get_event_loop().run_in_executor(None, _run_labor_extract_compare, run_id)`。
- `bonus_platform/app.py` 已识别 Vercel `/tmp` 临时存储场景，并在没有 Blob 后端时提示 UAT 不保存上传批次。
- `bonus_platform/engine/labor/blob_storage.py` 已提供 Vercel Blob 的上传、下载、列表、同步本地运行目录能力。
- `bonus_platform/engine/labor/runs.py` 已在 `SIGMA_LABOR_STORAGE_BACKEND=blob` 时同步 metadata 和文件到 Blob。
- `vercel.json` 当前设置 `SIGMA_WORKBENCH_HOME=/tmp/sigma-workbench`、`SIGMA_LABOR_STORAGE_BACKEND=blob`、`SIGMA_OVERSEAS_LABOR_ACCESS=uat`。

本 ADR 的目标是先确定 UAT/准上线架构方向，避免在未定架构前继续把 Serverless、Blob 和本地运行目录补丁式拼接。

## 决策约束

- 不得把继续使用 `run_in_executor` 作为 Vercel 生产长任务方案。
- 真实 PDF/Excel 不进入 Git，不发送外部 OCR 或外部模型。
- AI 只能生成候选建议，不得静默修改正式规则、结构化数据或最终报告。
- UAT 结果必须提示人工复核边界，不得宣称生产准确率已达标。
- 后台状态查询不能依赖单进程内存。
- 批次元数据、上传文件和报告要么持久化，要么明确限定为本地/内网执行。

## 方案比较

| 维度 | 模式 A：Vercel 前端/API + 持久化存储 + 外部耐久 Worker | 模式 B：海外劳务服务部署到长运行容器 | 模式 C：Vercel 只做页面/轻量 UAT，正式抽取在本地或内网执行 |
| --- | --- | --- | --- |
| 数据持久化 | Blob/Postgres/队列持久化批次、文件、报告 | 容器挂载盘或对象存储持久化，数据库记录状态 | Vercel 只存测试材料或轻量样例；正式材料留在本地/内网 |
| 长任务生命周期 | Worker 从队列消费，独立于请求生命周期 | 容器内任务进程或独立 worker 长运行 | 不在 Vercel 发起正式长任务 |
| 重试 | 队列重试、死信队列、失败原因持久化 | 进程级重试加任务表；需自建 watchdog | 本地/内网命令或服务重试；Vercel 只展示说明和结果 |
| 幂等性 | 需要 batch_id + idempotency_key + 状态版本 | 需要任务表唯一键和锁 | 本地命令以 manifest/run_id 控制；Vercel 上传链路可禁用 |
| 成本 | 需要外部队列、数据库、Worker 运行成本 | 需要容器平台和存储成本 | 最低，主要是 Vercel 页面和本地/内网算力 |
| 运维复杂度 | 高，需要队列、Worker、监控、权限和密钥轮换 | 中高，需要容器发布、进程监控、磁盘/对象存储 | 低到中，牺牲在线全流程体验 |
| 隐私 | 需要确认对象存储和 Worker 环境满足材料合规要求 | 材料可放内网，隐私控制更直接 | 正式材料不进入公网 UAT，隐私风险最低 |
| 本项目现有基础 | 已有 Vercel 页面和 Blob 雏形，但缺队列/Worker | 当前 FastAPI/Flask 风格服务较适合容器长运行 | 已有本地工具、黄金回归、测试材料验证，更贴近当前成熟度 |
| 对其他模块影响 | 可能需要共享认证、部署和环境配置调整 | 可尽量模块化部署海外劳务，减少共享页面改动 | 对其他模块影响最小 |
| 新增外部基础设施 | 是：队列、Worker、状态库/锁 | 是：容器平台、持久存储、监控 | 否或最少：仅保留现有 Vercel UAT |
| 上线适配 | 最接近在线 SaaS 体验 | 适合内网业务工具正式运行 | 适合业务先试页面、流程、报告和规则反馈 |

## 决策

短期采用模式 C 作为当前 UAT 边界：Vercel 只承载页面、权限、测试材料验证、说明文案和轻量只读体验；正式上传、抽取、核对和报告生成保留在本地或内网持久化环境。

中期推荐优先评估模式 B：将海外劳务抽取服务部署到长运行容器，并使用持久化目录或对象存储保存上传文件、metadata 和报告。该模式比模式 A 少一个外部队列/Worker 体系，和当前代码形态更接近，也更容易满足隐私和长任务要求。

模式 A 暂不作为当前项目默认落地方案，除非团队已经有可用队列、耐久 Worker、数据库、密钥管理和监控能力。

## 决策理由

1. 当前 Vercel Serverless 环境不适合承载 PDF/Excel 抽取这种长任务；继续修补 `run_in_executor` 会掩盖根因。
2. Blob 同步只能解决文件跨请求存在的问题，不能单独解决长任务生命周期、并发状态、幂等和失败恢复。
3. 当前真实材料黄金回归和业务 expected result 仍未完全闭环，不宜先追求公网在线全流程。
4. 业务 UAT 当前更需要验证页面流程、字段映射理解、报告可读性、异常分类和人工复核方式。
5. 本地/内网执行能更好保护真实材料，避免在未定合规边界前将材料上传到公网环境。

## 必须落实的边界

在模式 C 下，Vercel UAT 必须满足：

- 页面状态明确标注“UAT 试用版”。
- 正式上传后在线抽取不可用时，按钮必须禁用或给出明确原因。
- 不允许用户启动一个必然因 Serverless 生命周期中断的抽取任务。
- `测试材料验证` 与 `正式抽取并核对` 必须在页面文案上分开。
- 下载报告只允许下载当前环境真实存在且已持久化的报告。
- telemetry 只记录脱敏事件、阶段、错误码和耗时，不记录员工姓名、员工号、发票号或原始文件内容。

在模式 B 或 A 被正式采用前，不得把 Vercel UAT 标记为完整在线抽取环境。

## 后续实施门槛

### 模式 C 验收门槛

- Vercel 页面不开放开发中模块。
- UAT 权限只开放薪酬/报账核对试用角色。
- 页面明确说明 UAT 范围和正式抽取执行环境。
- 上传链路如果不能持久化，必须阻止在线抽取并提示下一步。
- 本地/内网环境能通过统一命令完成黄金回放。

### 模式 B 验收门槛

- 批次 metadata、上传文件和报告保存在持久化目录或对象存储。
- 新进程重启后可以读取批次状态和报告。
- 后台任务由容器内长运行任务管理器或独立 worker 执行，不依赖请求线程存活。
- 重复点击抽取不会产生不可控重复任务。
- 任务状态至少能映射 created、uploaded、mapping_required、queued、running、needs_review、completed、failed。
- 失败记录包含可诊断 errorCode、failureType、errorMessage、retryable、nextAction。

### 模式 A 验收门槛

- 队列、Worker、状态库和对象存储全部在隔离测试环境可用。
- 上传、下载、不存在对象、权限失败、网络超时、重试、同名对象、内容哈希和报告保存均有自动化测试。
- 状态更新具备版本控制或锁，避免并发覆盖。
- Blob 路径包含环境和批次边界，例如 `labor-runs/{env}/{run_id}/...`。
- 不使用生产 Blob 进行自动化测试。

## 当前风险登记

- LAB-P1-001：未关闭。当前代码仍有 `run_in_executor`，只能用于本地或长运行进程中的短期实现，不能作为 Vercel 生产长任务方案。
- LAB-P1-002：未关闭。Blob 同步代码存在，但缺少完整幂等、并发、一致性和隔离测试。
- LAB-P1-003：未关闭。黄金回归工具已推进，但业务 expected result 仍需人工确认。

## 本 ADR 带来的代码影响

本 ADR 不直接修改运行代码。下一步如果继续 M3，应优先做以下最小代码包之一：

1. 将 Vercel UAT 的正式上传抽取按钮按模式 C 明确禁用或引导到本地/内网执行。
2. 为 Blob 路径增加环境边界设计和对应 mock 测试。
3. 为本地/容器长运行模式设计任务状态表、幂等键和状态恢复测试。

## 非目标

- 不在本 ADR 中接入新的外部队列、数据库或 OCR 服务。
- 不改变现有核对口径。
- 不修改其他薪酬或报账模块。
- 不宣称当前结果已经达到生产准确率。
